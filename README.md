## 📌 1. 프로젝트 소개

Crazy Bingo는 여행, MT, 친목 모임 등에서 진행할 수 있는 팀 대항 빙고 퀴즈 게임입니다.

기존 PPT 기반 퀴즈 진행 방식의 불편함을 해결하기 위해 제작되었으며, 진행자는 전용 호스트 화면을 통해 문제를 관리하고 정답 판정 및 점수 계산을 수행할 수 있습니다.

참가자는 빙고판을 통해 게임을 진행하며, 문제를 맞힐 때마다 빙고를 완성하여 승리를 목표로 합니다.

- **개발 기간**: 2026.05 ~ 2026.06 
- **개발 인원**: 1명 

---

## 🛠 2. 기술 스택 (Tech Stack)
- **Engine**: Unreal Engine 5 (UE 5.6)
- **Language**: C++, Blueprint
- **Framework**: UMG (Unreal Motion Graphics), `UListView` Architecture
- **IDE**: JetBrains Rider

## 🚀 3. 주요 기능 (Key Features)

### 🔹 1) 런타임 퀴즈 가공 및 세이브 데이터 기반 관리 시스템
- **4종 멀티 퀴즈 타입 지원**: 단답형, 객관식, 초성 퀴즈, 유튜브 음악 퀴즈 등 각기 다른 데이터 구조를 가진 문제 유형을 완벽히 지원하며, 동적 UI 분기를 통해 실시간으로 폼을 편집할 수 있습니다.
- **유연한 세이브 데이터 아키텍처**: 호스트가 커스텀하게 작성한 문제셋을 세이브 데이터로 영구 보존할 수 있습니다. 게임 시작 시 **[어떤 세이브 데이터를 불러올 것인지]**와 **[이 중 몇 개의 문제를 게임에 사용할 것인지]**를 진행자가 자유롭게 스케일링하여 선택할 수 있는 유연성을 제공합니다.
- **DataTable 기반 직렬화**: 런타임 중 호스트가 자유롭게 생성, 편집한 가상 데이터는 최종적으로 데이터 테이블 구조와 안전하게 매칭되어 무결성 있게 직렬화 및 관리됩니다.

### 🔹 2) 가상화 리스트뷰(UListView) 기반 문제 테이블 관리
- **메모리 최적화 렌더링**: 대량의 문제를 버벅임 없이 안정적으로 관리하기 위해 `IUserObjectListEntry` 인터페이스와 가상 데이터 오브젝트를 적용했습니다. 화면에 보이는 만큼만 위젯을 풀링(Pooling)하여 렌더링 비용을 대폭 최적화했습니다.
- **독립 컬럼 아키텍처 (UX 개선)**: 기존의 유지보수가 불가능했던 단순 문자열 포맷팅 결합 방식을 탈피했습니다. **[문제 내용 / 카테고리 / 점수 / 문제 유형]**을 각각 독립적인 컬럼 블록으로 완전히 분리 레이아웃화하여 호스트가 수많은 문제 정보를 한눈에 판별할 수 있도록 가독성을 극대화했습니다.
- **실시간 데이터 바인딩**: 리스트뷰에 장전된 아이템 슬롯을 호스트가 선택하는 즉시 세부 편집 디테일 폼과 연동되어 실시간 데이터 수정 및 개별 소거가 가능합니다.

### 🔹 3) 체크박스를 활용한 무결성 다중 일괄 삭제(Multi-Delete) 시스템
- **명시적 다중 컨트롤 UX**: 목록 내의 행마다 독립적인 체크박스를 배치하여, 호스트가 제어(일괄 삭제 등)하고자 하는 문제들을 직관적이고 가시적으로 인지하고 다중 조작할 수 있도록 안전장치를 마련했습니다.
- **양방향 상태 동기화**: 리스트뷰 위젯이 스크롤되어 화면 밖으로 밀려나 파괴(가상화)되더라도 체크 상태가 무의미하게 증발하지 않도록, Row 위젯의 체크박스 상태를 가상 데이터 오브젝트(`UCB_QuestionListData`)와 실시간으로 연동하여 보존합니다.

### 🔹 4) 호스트 전용 실시간 게임 세션 컨트롤러
- **진행자 핵심 대시보드**: 게임 진행 중 현재 출제된 문제의 **[정답]**과 **[힌트]**를 호스트 화면에만 직관적으로 실시간 모니터링 피드백을 제공하며, 이를 바탕으로 정확하고 공정한 승자 판정을 내릴 수 있도록 지원합니다.
- **글로벌 게임 매니지먼트**: 라운드별 승리 팀 판정, 팀별 점수 실시간 합산 및 가감 기능, 그리고 전체 빙고 진행 스냅샷 상태를 완벽하게 제어하여 서버/세션에 실시간으로 브로드캐스팅합니다.



## 💡 4. 기술적 도전 과제

### 🔹 1) UI 머티리얼(Material)을 활용한 동적 배경 제작 및 최적화

**문제 상황 (Challenge)**  
레크리에이션 게임 특성상 적합한 배경 에셋을 확보하기 어려웠고, 단순 이미지 기반 UI는 반복 패턴으로 인해 시각적 단조로움과 용량 증가 문제가 있었습니다.

**해결 방안 (Resolution)**  
단순 텍스처 이미지 대신, UMG 위젯 구조와 UI 전용 머티리얼(User Interface Domain)을 결합하여 동적 배경을 직접 구현했습니다.

- `Border`, `Overlay` 등 UMG 컴포넌트를 활용한 기본 UI 레이아웃 구성
- 머티리얼 내 수학적 연산을 이용한 Procedural Grid 패턴 생성
- `Panner` 노드를 활용한 지속적인 텍스처 이동 효과 적용

**성과 (Result)**  
별도의 이미지 리소스 없이도 머티리얼 연산만으로 프로젝트 콘셉트에 맞는 동적인 배경을 구현했으며,  
리소스 용량을 최소화하면서 UI 가독성과 시각적 완성도를 동시에 확보했습니다.

---

### 🔹 2) YouTube 링크 재생 구조 개선 및 안정성 확보

**문제 상황 (Challenge)**  
초기에는 UMG `WebBrowser` 위젯을 이용해 YouTube 영상을 인게임에서 직접 재생하는 구조를 사용했습니다.

이 과정에서 다음과 같은 문제가 발생했습니다.

- WebBrowser 위젯 크래시 및 런타임 불안정성
- YouTube 정책 변경에 따른 재생 차단 가능성
- CEF(Chromium Embedded Framework) 기반 브라우저 유지보수 부담 증가

**해결 방안 (Resolution)**  
인게임 브라우저 재생 구조를 제거하고, URL 기반 외부 브라우저 실행 방식으로 아키텍처를 변경했습니다.

- YouTube URL (`watch?v=`, `youtu.be/`) 파싱 로직 구현
- 필요 시 `t=` 파라미터를 포함한 영상 정보 추출
- 정제된 URL을 기반으로 `FPlatformProcess::LaunchURL()`을 통해 OS 기본 브라우저 실행

**성과 (Result)**

- YouTube 정책 및 WebBrowser 의존성 제거로 안정성 확보
- 엔진 내부 WebBrowser 사용으로 인한 크래시 이슈 제거



### 🔹 3) 에디터 전용 모듈 의존성으로 인한 패키징 빌드 크래시 해결 (DesktopPlatform → Win32 API)

**문제 상황 (Challenge)**  
문제 추가 화면에서 호스트가 로컬 이미지 파일을 선택할 수 있도록 `IDesktopPlatform::OpenFileDialog()`를 활용한 파일 탐색기 호출 기능을 구현했습니다.

에디터(PIE) 환경에서는 정상적으로 동작했지만, 독립형 Windows 패키징 빌드로 구동 시 해당 함수 호출 시점에 즉시 **FatalError**가 발생하며 게임이 강제 종료되는 문제가 발생했습니다.

**원인 분석 (Analysis)**  
- **에디터 전용 모듈의 한계**: `DesktopPlatformModule`은 언리얼 엔진 에디터 프로세스에 종속된 에디터 전용(Editor-only) 모듈로, 패키징된 게임 빌드 타겟에는 포함되지 않습니다.
- 에디터에서는 에디터 자체가 이미 해당 모듈을 로드하고 있어 문제없이 동작했지만, Shipping/Development 게임 빌드에는 모듈이 누락되어 `FDesktopPlatformModule::Get()` 호출이 실패하고 곧바로 크래시로 이어졌습니다.
- 즉, **런타임(게임 실행 환경)에서 OS 네이티브 파일 다이얼로그를 호출하는 기능 자체가 엔진 표준 API로는 지원되지 않는 영역**이라는 것이 핵심 원인이었습니다.

**해결 방안 (Resolution)**  
- 엔진의 `DesktopPlatform` 모듈을 완전히 배제하고, **Windows 순수 Win32 API(`GetOpenFileName`, `comdlg32.lib`)를 직접 호출**하는 방식으로 구조를 변경했습니다.
- `PLATFORM_WINDOWS` 전처리 매크로로 플랫폼을 분기하여 Windows 외 환경에서는 안전하게 경고 로그만 출력하도록 처리했습니다.
- `OPENFILENAME` 구조체를 통해 이미지 파일 확장자 필터(`.png`, `.jpg`, `.jpeg`)를 지정하고, `OFN_NOCHANGEDIR` 플래그로 다이얼로그 호출 후 언리얼 내부 작업 디렉토리가 오염되는 부작용을 방지했습니다.
- 부모 윈도우 핸들(`hwndOwner`)을 현재 게임 뷰포트의 OS 네이티브 핸들로 지정하여, 다이얼로그가 게임 창과 독립적으로 포커스를 잃는 현상 없이 자연스럽게 모달처럼 동작하도록 처리했습니다.

**성과 (Result)**  
- 에디터와 패키징 빌드 양쪽 환경에서 완전히 동일하게 동작하는 파일 선택 기능을 확보했습니다.
- 엔진 에디터 모듈에 대한 런타임 의존성을 제거하여, 빌드 환경 차이로 인한 크래시 가능성을 원천적으로 차단했습니다.
- 호스트가 실제 진행 현장(패키징된 단독 실행 파일)에서도 로컬 PC에 저장된 이미지를 자유롭게 불러와 문제에 첨부할 수 있게 되었습니다.

│       ├── CB_SaveSlotRow.h         # 세이브 팝업 내 가상화 리스트뷰 전용 단일 행(Row) 컴포넌트
│       ├── CB_GameSetup.h           # 빙고 규격 선택, 파일 데이터 검증 및 호스트 창 기동 설정 위젯
│       ├── CB_BingoBoard.h          # 가변 빙고판 빌드, 실시간 빙고 연산 및 올킬 예외 판정 메인 보드
│       ├── CB_BingoScoreBoard.h     # 천 단위 콤마 표기 스코어 및 팀 컬러 실시간 동기화 전광판 UI
│       ├── CB_QuestionBoard.h       # 런타임 이미지 에셋 로드 및 유형별 위젯 스위칭 중앙 문제 보드
│       └── CB_HostPanel.h           # 독립 슬레이트 창(SWindow)으로 구동되는 진행자 원격 제어 콘솔
