# 🖥️ CB_GameSetup - 게임 설정 및 진행자 창 생성 시스템

> 게임을 본격적으로 시작하기 전, 빙고판 크기(3x3 ~ 7x7)를 결정하고 저장된 세이브 파일(.sav)을 선택하여 유효성을 검사하는 메인 설정 화면 위젯입니다.
> 플레이에 충분한 문제가 확보되었는지 자동 검증하는 방어 로직과, 게임 시작 시 진행 전용 외부 독립 슬레이트 윈도우(SWindow)를 동적으로 생성 및 띄워주는 연동 아키텍처를 포함합니다.

---

## 📌 1. 개요

- **클래스**: `UCB_GameSetup` (`UUserWidget` 상속)
- **역할**: 빙고 규칙 바인딩, 로컬 세이브 파일 탐색 및 데이터 역직렬화, 문제 수 기반 게임 시작 잠금/해제 검증, 슬레이트 기반 호스트 패널 팝업
- **연동 대상**: `UCB_SaveSlotData`(리스트뷰 바인딩 데이터), `UCB_BingoBoard`(인게임 플레이 보드), `UCB_HostPanel`(진행자 패널 콘솔 위젯)

---

## 🚀 2. 주요 기능

### 🔹 1. 빙고 크기별 동적 문제 수 유효성 검증 (Setup Validation)
선택한 빙고판의 크기(`3x3` ~ `7x7`)에 따라 필요한 최소 문제 개수(빙고 칸 수)를 실시간 계산하고, 선택한 세이브 파일의 실제 데이터 수와 대조하여 게임 진입을 안전하게 통제합니다.

**구현 내용**
- `BingoSizeComboBox`에서 선택된 옵션을 파싱하여 최소 요구 조건(`RequiredCount = BingoSize * BingoSize`)을 정립합니다.
- **준비 완료 (`bIsEnough == true`)**: 선택한 파일의 문제 수(`SelectedFileQuestionCount`)가 요구치를 만족하면 가이드 문구(`Text_InfoCheck`)에 성공 체크 표시(✓)를 띄우고 상태를 '● 준비 완료'로 변경한 후, 최종 진입 버튼(`Btn_LaunchGame`)을 활성화(`SetIsEnabled(true)`)합니다.
- **문제 부족 (`bIsEnough == false`)**: 문제 데이터가 하나라도 부족하여 인게임 셔플 시 대참사(크래시 혹은 인덱스 부족 오류)가 날 위험이 감지되면 경고 안내(✗ 부족) 및 '● 문제 부족' 상태로 비주얼을 교체하고 버튼을 완벽히 잠가 오작동을 차단합니다.

### 🔹 2. 리스트뷰 연동 및 실시간 파일 메타데이터 프리뷰
왼쪽 세이브 슬롯 목록에서 특정 항목을 마우스로 클릭할 때마다, 해당 파일 내부를 즉각 선 탐색하여 우측 상세 요약 패널에 정보들을 실시간 렌더링합니다.

**구현 내용**
- `SaveFileListView` 아이템 클릭 델리게이트 인터페이스에 `OnSaveFileSelected`를 연동합니다.
- 선택된 항목의 파일명(`SlotName`)을 획득한 후 `LoadQuestionsFromSlot()` 함수를 기동하여 직렬화된 데이터 크기(Num)와 저장 시점의 타임스탬프(`SaveDateTimeString`) 메타데이터를 역순 수집합니다.
- 수집된 정보를 바탕으로 파일명(`Text_InfoName`), 총 문제 수(`Text_InfoCount`), 저장일(`Text_InfoDate`) UI 컴포넌트 텍스트를 전면 동기화한 후 밸리데이션 함수를 호출합니다.

### 🔹 3. 피셔-예이츠 기반 무작위 퀴즈 풀 생성 (Shuffle & Extraction)
게임 시작 조건을 통과하면 세이브 데이터의 순수 배열을 메인 엔진 라이프사이클 공간으로 전달하고 무작위 난수 기반의 완벽한 셔플을 단행합니다.

**구현 내용**
- 불러온 문제 로우 배열(`LoadedRawQuestions`)을 글로벌 싱글톤 스타일 객체인 `UCB_GameInstance` 내부 퀴즈 저장소 변수에 안전하게 이관합니다.
- 게임 인스턴스에 탑재된 `GetRandomQuestions(RequiredQuestionCount)`를 기동하여 내부적으로 피셔-예이츠(Fisher-Yates) 알고리즘 방식의 셔플을 거친 뒤, 최종 필요한 빙고판 규격 수만큼만 데이터를 정교하게 슬라이싱하여 최종 결과 풀을 확보합니다.

### 🔹 4. 진행자 전용 독립 슬레이트 윈도우 생성 (Slate Windows Integration)
인게임 화면과 별개로 보드게임 마스터(진행자)가 세컨드 모니터나 독립된 개별 창에서 게임을 조작할 수 있도록 런타임에 네이티브 OS 윈도우 창을 개설하고 위젯을 주입합니다.

**구현 내용**
- 로컬 플레이어 컨트롤러를 기반으로 호스트 전용 UMG 위젯 클래스인 `UCB_HostPanel`을 동적 생성합니다.
- 언리얼 엔진 슬레이트(Slate) 프레임워크 핵심 매크로인 `SNew(SWindow)` 인터페이스를 호출하여 타이틀명 설정, 크기 지정(`800x1200`), 해상도 스케일러 고정 조치(`SDPIScaler`), 최대화 잠금 옵션이 반영된 OS 가상 창 뼈대를 정의합니다.
- `TakeWidget()` 함수를 통해 완성된 호스트 패널 UMG 비주얼 리소스를 네이티브 슬레이트 위젯으로 강제 변환하여 윈도우 콘텐츠 콘텐츠 영역에 밀어 넣습니다.
- 최종적으로 `FSlateApplication::Get().AddWindow(NewWindow)`를 구동하여 운영체제 화면 위에 독립 조작 창을 완벽하게 인스턴싱하여 띄웁니다.
